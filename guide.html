使用说明

「谓无名」排版工具由两部分组成：一个是你正在用的在线排版工作台，打开即用、不需要任何安装；另一个是配套的 AI Agent Skill，让 Claude Code、Codex、Gemini 这类 Agent 能把 Word 文档直接转成公众号排版。本页讲后者怎么装，以及图片上传所依赖的 PicGo 图床怎么配。

目录
  1. 在线工作台：直接用
  2. 安装 Skill：Claude Code / Codex / Gemini
  3. 配置图床：PicGo 或 R2
  4. 常见问题

一、在线工作台：直接用

工作台是纯前端页面，不上传、不存储任何文稿，所有排版都在你自己的浏览器里完成。

操作方式
写稿左侧输入 Markdown + 谓无名自定义语法
预览右侧实时显示手机端效果
复制点右上「复制排版结果」或按 Ctrl+Enter，直接粘进公众号后台
查语法点「语法手册」展开完整语法参考
调排版左上「排版微调」面板，分正文 / 引文 / 图注三组，可改字体、字号、行距、字距
只是想排个版？ 那到这里就够了，下面两节都不用看。Skill 和图床是给「让 AI 自动处理整篇 Word 稿」这个场景准备的。

二、安装 Skill

Skill 就是一个装着说明书和脚本的文件夹。三家 Agent 的机制一样：各自有一个 skills 目录，把仓库克隆进去就算装好，重启 Agent 后自动识别。

1. 先备好依赖

  • Python 3.9+ —— 脚本只用标准库，不需要 pip 装东西
  • Node.js 18+ —— 渲染微信 HTML 用
  • LibreOffice —— 可选，只有处理老式 .doc 时才需要

2. 克隆到对应目录

按你用的 Agent 选一条。~ 在 Windows 下就是 C:\Users\你的用户名。

AgentSkill 目录
Claude Code~/.claude/skills/
Codex~/.codex/skills/
Gemini CLI~/.gemini/skills/

以 Claude Code 为例，换成上表里其它路径即可：

git clone https://github.com/Roloyty/weiwuming-wechat-formatter.git \
  ~/.claude/skills/weiwuming-wechat-formatter

Windows PowerShell：

git clone https://github.com/Roloyty/weiwuming-wechat-formatter.git `
  "$env:USERPROFILE\.claude\skills\weiwuming-wechat-formatter"

3. 装 Node 依赖

cd ~/.claude/skills/weiwuming-wechat-formatter
npm ci
装好长什么样。 目录里应该直接能看到 SKILL.md、scripts/、assets/、references/。SKILL.md 是 Agent 读的说明书，必须在这个文件夹的最外层 —— 如果不小心多套了一层目录，Agent 就找不到它。

4. 只想装到某个项目

Claude Code 和 Codex 支持项目级 Skill：把上面的路径换成项目根目录下的 .claude/skills/ 或 .codex/skills/，作用范围就只限该项目，适合某个仓库专用的 Skill。

Gemini CLI 这边只验证过全局目录，项目级是否支持请以官方文档为准。

5. 更新

cd ~/.claude/skills/weiwuming-wechat-formatter
git pull
npm ci

6. 怎么用

装好后不用背命令，直接对 Agent 说人话，它会自己去读 Skill：

把这份 Word 转成公众号排版：D:\稿件\书评.docx

Agent 会依次完成：提取 Word 结构 → 生成谓无名 Markdown → 本地图片传图床换成公网链接 → 渲染出可直接粘贴的微信 HTML，并校验模块顺序、语法配对这些容易出错的地方。

三、配置图床

为什么必须配。 Word 里的图片是文档包内部路径（word/media/image1.png），这种本地路径微信服务器抓不到，直接粘进公众号就是一片图裂。所以图片得先传到公网可访问的地方，换成 https:// 开头的链接 —— 这件事由 PicGo 代劳。

上传支持两种后端，都传到你自己的图床，本项目不提供也不代管任何公共图床：

后端说明凭据存放
picgo
（默认）		把图片递给你自己的 PicGo Server，用哪家图床由你在 PicGo 里决定PicGo 自己的配置，本项目完全不接触
r2
（可选）		S3 兼容接口直传你自己的 Cloudflare R2 存储桶，不必常驻 PicGo GUI本地 ~/.weiwuming/image-host.json 或环境变量

后端按此顺序决定：命令行 --backend → 环境变量 WEIWUMING_IMAGE_BACKEND → 配置文件 "backend" 字段 → 自动（R2 五项配全了就用 R2，否则用 PicGo）。不配 R2 的话行为和以前完全一样，下面先讲 PicGo。

1. 装 PicGo 并选好图床

  1. 安装 PicGo GUI 2.2 及以上版本。
  2. 在 PicGo 里配置你自己的图床（GitHub、S3、阿里云 OSS、腾讯云 COS 等都行），填好各自的凭据。
  3. 把它设为「当前图床」 —— 这步最容易漏，配了但没选中，上传照样失败。
  4. 打开 PicGo 的 Server 设置，确认服务已启动，默认监听 http://127.0.0.1:36677。

2. 验证连通

默认地址开箱即用，不用改任何配置。先检查一下：

python scripts/upload_image.py --check

正常会打印 PicGo Server 可用和缓存文件位置。

3. 改过默认地址才需要配

如果你改过 PicGo Server 的端口或设了密钥，建 ~/.weiwuming/image-host.json：

{
  "picgo": {
    "api_url": "http://127.0.0.1:36677/upload",
    "server_secret": "",
    "timeout": 90
  }
}

也可以用环境变量，优先级高于配置文件：

PICGO_API_URL=http://127.0.0.1:36677/upload
PICGO_SERVER_SECRET=可选的服务密钥
PICGO_TIMEOUT=90

4. 手动传图

python scripts/upload_image.py images/cover.jpg
python scripts/upload_image.py --json images/*.jpg

输出是「本地路径 + 制表符 + 公网 URL」。同一张图重复传不会真的重复上传 —— 脚本按内容哈希在 ~/.weiwuming/picgo-upload-cache.json 里做了幂等缓存，反复重排同一篇稿子不会把图床刷爆。

5. PicGo Core 命令行版

如果你用的是命令行版而非 GUI：

命令作用
python scripts/setup_picgo.py --status查 PicGo CLI 是否装了、什么版本
python scripts/setup_picgo.py --login走官方浏览器流程登录 PicGo Cloud
python scripts/setup_picgo.py --configure-uploader配置 GitHub / S3 / OSS / COS 等第三方图床凭据
关于登录。 --login 只负责 PicGo Cloud 自身的登录，token 由 PicGo 保存，本项目不读取。第三方图床仍要单独配凭据。另外还有个 --sync-config 会调用官方云配置同步，可能上传你的本地配置并要求解决冲突，所以不会自动执行，需要你手动调用。

6. 改用 Cloudflare R2（可选）

如果你不想让 PicGo GUI 一直挂着，或者要在没有桌面环境的机器上跑，可以直传自己的 R2 桶。走 S3 兼容接口、AWS SigV4 签名，只用 Python 标准库，不需要装 boto3。

先准备三样东西：一个自己的 R2 存储桶；一个绑定到该桶的公开访问域名（没有它，图片传上去了也不可公开访问）；一对 R2 的 S3 API 凭据。

然后写进 ~/.weiwuming/image-host.json：

{
  "backend": "r2",
  "r2": {
    "account_id": "",
    "access_key_id": "",
    "secret_access_key": "",
    "bucket": "",
    "domain": "https://img.example.com"
  }
}

也可以用环境变量 R2_ACCOUNT_ID / R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY / R2_BUCKET / R2_DOMAIN。验证与上传：

python scripts/upload_image.py --check --backend r2
python scripts/upload_image.py --backend r2 images/cover.jpg

--check 会对存储桶发一个签名 HEAD 请求，同时验证凭据有效和桶存在。对象键是 weiwuming/<内容hash前16位><后缀>，同内容的图只会占同一个对象，不会堆垃圾文件。想临时切回 PicGo 用 --backend picgo。

R2 凭据是明文存在本地文件里的，而且有写权限。别把这个文件提交进任何仓库，也别放到会同步至公开位置的目录。建议单独签发一对只对该桶有写权限的凭据，不要复用账号级密钥。

7. 安全

  • PicGo Server 建议只监听 127.0.0.1。若要监听局域网地址，请启用 shared secret 并加防火墙限制。
  • 图床凭据只留在 PicGo 配置里，不要提交进任何仓库。
  • 上传后的图片通常公网可访问，不要传隐私或未公开的资料。

四、常见问题

现象原因与处理
Agent 说找不到这个 Skill 确认 SKILL.md 在 skill 文件夹最外层、没多套一层目录，然后重启 Agent
上传报配置无效（退出码 2） PicGo 后端：没选中当前图床，或 Server 没启动。R2 后端：五项配置没填全。先跑 --check 确认
R2 返回 403 / 404 403 是凭据无效或没有该桶写权限；404 多半是桶名或 account_id 写错。--check 会直接暴露这两类问题
R2 传成功但图片打不开 domain 没正确绑定到该桶，或桶未开启公开访问。上传只保证对象写入，能否公开读取取决于域名与桶的访问设置
粘进公众号后图片全裂 说明图片还是本地路径。检查稿子里的图片链接是不是 https:// 开头
渲染被拒绝，提示模块顺序错 文章有固定顺序：编者按 → 正文 → 目录 → 注释 → ---[note] → 作者简介 → 译者简介 → 延伸阅读 → 两条 staff → 关注区。编者按必须是第一个非空内容，上方不能放标题
粘进公众号后行距、字距变了 公众号编辑器会吃掉部分内联样式。工作台已把行距字距挂在卡片最外层来规避，若仍有出入，用「排版微调」面板改完再复制
npm ci 失败 确认 Node 18+，并且是在 skill 文件夹里执行的
